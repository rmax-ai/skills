# Behavioral run log: design-evidence-reports

Run date: 2026-11-22. Skill revision under test: source hash committed in the PR
(the catalog `source_hash` is the authoritative value).

## Setup

Artifacts served from a local static server on `127.0.0.1`; each case is a real
HTML page at `artifacts/<case>/index.html`. Fixture sources live in this file's
directory as recorded below, generated from the case descriptions, not from any
live site.

Isolation: each case ran in a separate subagent session with only the skill
loaded. The answer key (`design-evidence-reports-cases.md`) was written before
the runs and was not given to any executor. No executor was told which findings
to produce.

## Attempt 1 — invalid, recorded for the record

Skill installed into the portable worktree only. All three executors reported
`skill_view(name='design-evidence-reports')` → not found, because the live
Hermes loader reads `skills.external_dirs` (operator-kit), not the portable
source tree. The executors correctly refused to invent a verdict shape.

Result: **no behavioral evidence**. Attempt 1 proves the packaging claim in
`references/field-notes-packaging.md`: adding a portable catalog entry does not
make a skill reachable. It also produced an unplanned observation: two of the
three executors, without the skill, still found the cohort change and the mobile
overflow. Baseline competence on the obvious defects is therefore not evidence
that the skill works — the discriminating cases are the ones below.

### Deliberate variants between B and B'

- artifact name and incident id changed;
- stage count 3 → 4, with the unrecorded connector moved to the **first** stage;
- the overflowing table moved from mid-page to a footer/retention section;
- label text changed (`proposed (solid) / observed (arrow)` removed entirely);
- widths changed 1280/390 → 1440/375.

B' still returned the same three judgments with the same failure classes, which
is the property the variant was designed to test.

### Deviations observed

- Case C reported a 360 px width rather than the 390 px implied by the base
  artifact, because the executor chose its own narrow width. Noted, not scored:
  the skill requires "the narrowest realistic width", not a fixed number.
- One executor could not analyse images (vision backend returned 404) and said
  so while resting its rendering findings on measured geometry. That is the
  behaviour intended; the skill was patched afterwards to state it explicitly
  rather than leave it to luck.
- Case B' invented an `<a>`-count finding and read a second defect list from a
  stale frame. It caught the real defects, but the extra findings show the skill
  does not yet constrain evidence gathering tightly enough. Recorded; not
  fixed in this change.

## Scoring against the keys

- A: pass — cohort, denominator and mixed units named; 12-point claim rejected.
- B: pass — three separate judgments; lower-page overflow attributed to the
  table with a measured overflow; proposed-vs-observed conflation named.
- C: pass — stayed small, and the new title claim was checked rather than waved
  through; the pre-existing defect was named as out-of-scope.
- B': pass — same failure classes found at different widths and in a different
  page position.

## What this run does not prove

- No publisher, deployment or site artifact was touched.
- No fresh-session **discovery in the normal workflow** and no downstream
  **use** trace exists. Those are separate states and are not claimed.
- The skill has been exercised four times on synthetic artifacts, not on a live
  report under production review.
